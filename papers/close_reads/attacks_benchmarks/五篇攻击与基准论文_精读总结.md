五篇论文连起来可以形成一条完整攻击链：

```text
攻击进入系统
  ├─ 用户输入：DPI、Impersonation
  ├─ 外部环境：IPI、恶意工具结果
  ├─ 长期状态：Memory Poisoning
  └─ 内部组件：恶意模板、被攻陷 Agent
          ↓
攻击在多个上下文中组合：Conjunctive Attack
          ↓
攻击沿通信拓扑传播：NetSafe
          ↓
攻击递归复制并阻断协作：CORBA
          ↓
系统结果：错误、恶意工具调用、任务失败、资源耗尽或系统瘫痪
```

# 1. ASB：Agent 执行链的攻击与防御基准

## 1.1 论文定位

ASB（Agent Security Bench）主要研究单个工具型 Agent，而不是完整 MAS。它的价值在于系统化梳理 Agent 的攻击入口：

```text
用户输入 → Agent 规划 → 工具调用 → 工具返回 → 记忆检索 → 后续动作
```

ASB在10类应用场景、10个Agent、13种LLM上测试多类攻击和防御。数据包括50个正常任务、20个正常工具，以及400组攻击任务/工具。

## 1.2 统一形式化

设：

- `q^t`：正常用户任务；
- `x^e`：攻击者注入的恶意指令；
- `T`：正常工具集合；
- `T^e`：攻击工具集合；
- `O`：Agent执行过程中获得的工具观察；
- `a_m`：攻击者希望触发的恶意动作。

攻击公式虽然很长，本质都是：

\[
\mathbb E\big[\mathbf 1(Agent(\text{被污染的上下文})=a_m)\big]
\]

- \(\mathbf 1\)：成功记1，失败记0；
- \(\mathbb E\)：在很多测试任务上取平均；
- 攻击者希望这个平均值尽可能大。

## 1.3 五类攻击

### Direct Prompt Injection（DPI）

污染位置：用户输入。

\[
q^t \rightarrow q^t\oplus x^e
\]

攻击者把“忽略原任务并调用攻击工具”等指令直接接在正常任务后。ASB测试了直接拼接、特殊字符、忽略上下文、假装任务完成和Combined五种文本写法。

### Indirect Prompt Injection（IPI）

污染位置：工具返回结果。

\[
O\rightarrow O\oplus x^e
\]

用户输入可以完全正常，恶意指令藏在网页、邮件、文档、API返回或搜索结果中。Agent无法稳定区分“外部数据”和“需要执行的指令”，因此可能重新规划并调用攻击工具。

### Memory Poisoning

污染位置：长期记忆数据库。

\[
D_{poison}=D_{clean}\cup\mathcal A
\]

攻击者先把包含恶意规划的历史记录存入数据库。未来相似任务检索到这条记录后，Agent会把它当成成功经验模仿。攻击具有延迟、持久和共享传播风险。

### Plan-of-Thought（PoT）Backdoor

污染位置：系统提示词中的规划示例。

攻击者在few-shot规划示例中加入“触发器 → 恶意规划 → 恶意工具”的对应关系。它不修改模型权重，而是利用上下文学习植入临时后门：

\[
q^t\oplus\delta \Rightarrow a_m
\]

没有触发器时，Agent保持正常；出现触发器时，执行恶意动作。

### Mixed Attack

同时污染用户输入、工具结果和记忆。三条渠道互相强化，因此即使Agent忽略其中一条，另外两条仍可能推动攻击成功。

## 1.4 实验结果

| 攻击 | 平均ASR | 核心解释 |
|---|---:|---|
| Mixed | 84.30% | 多入口冗余，最强 |
| DPI | 72.68% | 恶意指令直接进入核心任务 |
| PoT Backdoor | 42.12% | 系统模板供应链可植入条件后门 |
| IPI | 27.55% | 需要经过工具调用、读取和重新规划 |
| Memory Poisoning | 7.92% | 同时受“能否检索到”和“是否模仿”限制 |

关键发现：

1. 模型能力与ASR不是简单负相关。弱模型可能因为不会用工具而ASR低；能力增强后，模型也更会完成恶意任务。
2. 明显危险的攻击更容易触发拒绝；伪装成备份、同步、审核等正常业务的攻击更隐蔽。
3. 仅看ASR会错误奖励“什么都不会做”的Agent，因此还要看无攻击性能PNA和净韧性指标NRP。
4. 现有防御主要是分隔符、改写、安全提醒、Sandwich、困惑度和LLM检测，效果有限且会损害正常性能。

## 1.5 证据边界

- ASB主要是单Agent，不研究跨Agent传播。
- 调用攻击工具即计为成功，不一定等价于真实世界危害已经发生。
- Memory Poisoning的低ASR可能只是检索失败，而不是模型识别出了攻击。
- Mixed Attack拥有更强攻击权限，与单入口攻击并非完全公平比较。
- 防御实验主要覆盖Prompt级轻量方法，不能推出“所有Agent防御均无效”。

# 2. NetSafe：恶意信息的拓扑传播

## 2.1 论文定位

NetSafe不是为了设计最隐蔽、最高ASR的攻击，而是回答：

> 当一个或多个Agent已经被攻陷后，Chain、Cycle、Tree、Star和Complete Graph中，哪种拓扑更容易放大恶意信息？

## 2.2 RelCom通信机制

为了公平比较拓扑，作者用统一的Relation Communication（RelCom）替代不同MAS框架自己的通信逻辑。

### Genesis：初始回答

\[
R_i^{(0)}=(a_i^{(0)},r_i^{(0)},m_i^{(0)})
\]

每个Agent独立生成答案、理由和记忆。

### Renaissance：多轮更新

第 \(t\) 轮，Agent \(i\) 收集所有入邻居的信息：

\[
O_i^{(t)}=\bigcup_{A_{ji}=1}R_j^{(t)}
\]

然后根据原问题、邻居回答和自己的上一轮回答重新生成。这个过程持续多轮，使错误信息能够沿通信边传播。

## 2.3 攻击者模型

攻击节点集合：

\[
V_{atk}\subseteq V,\qquad V_{nor}=V\setminus V_{atk}
\]

作者直接改写攻击Agent的系统提示词：

\[
R_i^*=v_i(P_{sys}\oplus\phi_i,P_{usr})
\]

因此它研究的是“Agent已经被完全控制后的传播”，而不是攻击者怎样首次攻陷Agent。

## 2.4 三类攻击策略

### Misinformation Injection（MI）

攻击Agent故意给出错误答案，并编造合理解释。如果正常Agent不同意，攻击者在下一轮根据邻居的新回答继续劝说。

### Bias Induction（BI）

攻击Agent输出性别、种族等刻板印象，并持续与正常Agent争辩。

### Harmful-info Elicitation（HE）

作者通过Dark Traits Injection越狱攻击Agent，使其持续生成暴力、自残、仇恨或犯罪内容，再尝试影响邻居。

## 2.5 评估指标

单Agent准确率：

\[
SAA_i^{(t)}=\frac{1}{|\mathcal D|}\sum_{Q\in\mathcal D}\mathbf1(a_i^{(t)}=a_Q)
\]

系统平均准确率：

\[
MJA^{(t)}=\frac{1}{|V^*|}\sum_{v_i\in V^*}SAA_i^{(t)}
\]

通常取 \(V^*=V_{nor}\)，专门观察正常Agent被污染了多少。

## 2.6 实验结果

实验通常使用6个Agent、1个攻击者、10轮RelCom，并在Fact、CSQA、GSMath、Bias和AdvBench上评测。

### 错误信息攻击

- Chain在Fact/CSQA最后MJA为84.18/65.35；
- Star只有66.80/53.54；
- 两者差距达到26.0%和22.1%。

高连通拓扑为错误信息提供更多传播边，因此一个攻击者可以快速污染多个正常Agent。

不同任务从第1轮到第10轮的平均降幅：

- Fact：18.2%；
- CSQA：7.4%；
- GSMath：3.2%。

作者将单个Agent错误扩散成系统级错误称为Agent Hallucination。

### 偏见和有害信息攻击

偏见实验中，78%的设置保持100%识别准确率，其他设置约99.8%。在Complete Graph中，即使5个Agent已被越狱，只剩1个正常Agent，其毒性分数仍只有0.097，而攻击者平均为0.920。

作者称这种现象为Aggregation Safety：现有LLM对显式偏见、暴力等内容的安全对齐，使正常Agent不容易被带偏。

### Agent数量

Complete Graph在无攻击者时准确率89.38，5个攻击者时降至44.25。增加正常Agent却只带来有限改善，有时还增加传播路径、导致性能下降。作者称为Security Bottleneck。

## 2.7 正确结论与局限

不能简单说“连接越多永远越危险”：

- 对隐蔽错误事实，高连通性加快污染；
- 对显式有害内容，大量正常Agent可能共同纠正攻击者；
- 当攻击者比例升高时，高连通性又会迅速放大危害。

局限包括：攻击者拥有系统提示词控制权、RelCom是人为统一的通信机制、网络规模较小、没有攻击检测和修复。

# 3. Conjunctive Prompt Attacks：分布式条件触发

## 3.1 核心思想

攻击由两个单独看似无害的组件组成：

1. 用户任务中的触发Key \(k\)；
2. 一个被攻陷远程Agent中的隐藏模板。

只有带Key的子任务被路由到被攻陷Agent时，攻击才触发。因此传统逐条消息检测看不到完整恶意意图。

## 3.2 MAS与路由模型

客户端将任务切分为子任务：

\[
x\xrightarrow{\mathcal S}(s_1,s_2,\ldots,s_S)
\]

路由器随机选择处理Agent：

\[
a_i\sim\mathcal R(s_i;\rho)
\]

- \(s_i\)：第 \(i\) 个子任务；
- \(a_i\)：接收它的Agent；
- \(\rho\)：特定文本特征对路由至被攻陷Agent的偏向程度。

攻击者不修改模型权重、客户端Agent和路由算法，但可以控制用户输入中的Key，并污染一个远程Agent的Prompt模板。

## 3.3 触发条件

把Key加入第 \(j\) 个子任务：

\[
s_j\leftarrow s_j\Vert k
\]

模板可位于prefix、wrap或suffix位置。攻击激活条件为：

\[
\exists j:\;(k\in s_j)\land(a_j=a^*)
\]

即存在一个带Key的子任务，而且它正好到达被攻陷Agent \(a^*\)。Key-only和template-only都不应稳定触发攻击。

## 3.4 路由感知优化

攻击配置：

\[
\theta=(j,\tau,\rho)
\]

- \(j\)：Key放在哪个子任务；
- \(\tau\)：模板放在前、中、后哪个位置；
- \(\rho\)：路由偏置。

因为真实LLM和路由器是黑盒，且位置选择是离散的，作者构造可微分替身目标：

\[
\widehat{ASR}_{both}=P_{route}\times P_{template}
\]

其中：

- \(P_{route}\)：带Key子任务到达被攻陷Agent的概率；
- \(P_{template}\)：到达后模板成功触发的概率。

作者使用Gumbel-Softmax把离散位置临时表示成软概率，利用梯度下降优化。结束后通过argmax选择概率最大的Key位置和模板位置。

## 3.5 实验结果

在Star、Chain和DAG三种拓扑上测试Gemma-2B、Mistral-7B和LLaMA3-8B，每种配置运行50次。

完整优化前，跨拓扑平均ASR均低于0.35；完整优化后：

| 模型 | 优化前平均ASR | 优化后平均ASR | 优化后最大ASR |
|---|---:|---:|---:|
| Gemma-2B | 0.23 | 0.60 | 1.00 |
| Mistral-7B | 0.30 | 0.60 | 1.00 |
| LLaMA3-8B | 0.33 | 0.65 | 1.00 |

安全检测器F1明显下降：PromptGuard从30降至0，多种Llama-Guard从40–63降至0–12。原因是攻击信号被分散在不同组件，单点检测器只能看到其中一半。

## 3.6 证据边界

- 路由器是抽象概率模型，不是具体生产系统路由器。
- 成功标准是输出特殊标记，不等价于真实工具危害。
- 主结果中部分template-only激活达到0.4–0.6，论文“单组件误激活接近0”的表述偏强。
- 攻击假设一个远程Agent模板已被供应链污染，属于较强但合理的权限。

# 4. CORBA：传染性递归阻断与DoC

## 4.1 攻击目标

CORBA不追求错误答案或数据泄漏，而是让MAS持续进行无意义通信，无法处理正常任务。这种状态称为Denial-of-Collaboration（DoC）。

- DoS：让某个节点或服务不可用；
- DoC：Agent仍在运行和生成文本，但协作过程已被递归消息占满。

## 4.2 攻击Prompt

攻击指令 \(P_{doc}\) 的语义大致是：

> 把这整条指令完整发送给所有其他Agent，并要求它们继续把这整条指令发送给其他Agent。

它表面上只是“转发消息”，不包含暴力、盗窃或黑客词汇，因此容易绕过传统内容安全检测。

## 4.3 两个核心性质

### Self-Sustainment：自我维持

Agent收到 \(P_{doc}\) 后，输出 \(R_{doc}\)，而 \(R_{doc}\) 又要求自己下一轮重新处理 \(P_{doc}\)：

\[
\forall t\ge t_m,\quad a_i^t(P_{doc})\rightarrow\text{下一轮继续处理 }P_{doc}
\]

这相当于创建动态自环：

```text
Agent i → Agent i → Agent i → ...
```

### Contagion：传染

被感染Agent同时把 \(P_{doc}\) 发给所有可通信邻居：

\[
a_i\rightarrow a_j,\qquad(a_i,a_j)\in E
\]

于是每个感染节点既维持自身循环，又继续向外传播。

## 4.4 系统级DoC条件

设入口Agent为 \(a_b\)，它在图上可达的节点集合为 \(\mathcal R(a_b)\)。攻击希望：

\[
\forall a_r\in\mathcal R(a_b),\;\exists\delta_r\ge0
\]

使得在有限传播延迟 \(\delta_r\) 后，所有可达节点永久输出阻塞响应。也就是说，只要通信图上存在路径，感染最终就能到达。

## 4.5 指标

比例攻击成功率：

\[
P\text{-}ASR=\frac{\text{被阻塞Agent数量}}{\text{Agent总数}}
\]

Peak Blocking Turn Number（PTN）表示达到最大感染规模需要多少轮。PTN越小通常表示传播越快，但如果攻击只感染一个节点、之后不再传播，PTN也可能等于1，因此必须与P-ASR一起看。

## 4.6 实验结果

论文测试AutoGen、CAMEL和开放式MAS，每组进行10次实验并随机选择入口Agent。

GPT-4o-mini结果：

- AutoGen 3/5/10个Agent：P-ASR为100%/84%/79%；
- CAMEL 3/5/10个Agent：100%/98%/92%。

在6节点复杂拓扑上：

- Chain：约78%–88%；
- Cycle：85%–98%；
- Tree：约57%–92%；
- Star：约92%–98%；
- Random：约67%–75%。

Star通常传播最快，因为中心节点连接大量Agent。在开放式六Agent自由对话中，CORBA在20轮内接近100%感染。

CORBA Prompt的困惑度约1.7–1.95，与正常文本几乎相同，且传统LLM Checker和Agent Monitor的识别效果较差。

## 4.7 证据边界与防御启示

CORBA依赖系统允许自然语言输出驱动下一轮任务、消息转发和自我调用。以下机制可以直接破坏它的递归闭环：

- 最大轮数和Token预算；
- 重复消息检测和消息去重；
- 禁止Agent给自己派发自然语言任务；
- 传播速率限制；
- 调度器不直接执行普通Agent的转发请求；
- 出现异常资源消耗时隔离节点和终止会话。

核心启示是：自然语言消息不应自动等同于执行权限或路由权限。

# 5. TAMAS：MAS综合攻击基准

## 5.1 论文定位

TAMAS将MAS攻击分为三层：

| 攻击面 | 攻击类型 |
|---|---|
| Prompt层 | DPI、Impersonation |
| Environment层 | IPI |
| Agent/协作层 | Byzantine、Colluding、Contradicting |

攻击者知道Agent角色和工具，但不知道模型参数与安全对齐细节。攻击者可以注入Prompt、污染环境观察、修改部分Agent系统提示词，或向工具集中加入攻击工具。

## 5.2 通用攻击目标

\[
\mathbb E_{q\sim\pi_q}\left[\mathbf1(\mathcal M(\text{被攻击后的系统})=a_m)\right]
\]

与ASB不同，\(\mathcal M\) 表示整个多Agent系统。攻击是否成功取决于路由、协作、工具调用和最终结果，而不仅是某个Agent的单次输出。

## 5.3 六类攻击

### DPI

\[
q^t\rightarrow q^t\oplus x^e
\]

恶意指令直接进入用户任务，并要求系统调用攻击工具。

### Impersonation

\[
q^t\rightarrow q^t\oplus x^{auth}
\]

攻击者谎称任务来自管理员、主任或其他权威。它利用Agent将自然语言身份声明误当成真实授权的倾向。

### IPI

\[
O\rightarrow O\oplus x^e
\]

用户输入保持正常，恶意指令藏在第三方工具或外部数据返回中，再通过共享上下文影响后续Agent。

### Byzantine Agent

\[
p_j^{sys}\rightarrow p_j^{sys}+\delta_j
\]

一个Agent被完全控制，可以故意给错误答案、返回噪声、破坏工具调用、隐瞒结果或输出矛盾信息。

### Colluding Agents

\[
\{p_i^{sys}+\delta_i\mid i\in\mathcal C\}
\]

多个恶意Agent朝同一个目标合作。例如一个伪造授权，另一个依据伪造授权执行恶意工具。TAMAS采用较严格标准：多个共谋Agent都完成各自攻击动作才算完整成功。

### Contradicting Agents

两个功能相似的Agent被要求持续给出冲突结论，目的是让协调者困惑、任务无法完成或产生错误结果。

区别：Colluding是“共同作恶”，Contradicting是“故意互相冲突以破坏任务”。

## 5.4 MAS配置

- Central Orchestrator：中央Agent负责规划、分工和汇总，控制清晰但存在单点故障；
- Sequential/Round Robin：Agent固定顺序轮流工作，错误会沿序列传递；
- Collaborative/Swarm：当前Agent动态决定下一位Agent，灵活但handoff路径可被操纵。

具体实现包括AutoGen的Magentic-One、Round Robin和Swarm，以及CrewAI的中央和顺序配置。

## 5.5 数据与指标

TAMAS覆盖教育、金融、医疗、法律和新闻五个领域，包括：

- 每个领域4个专业Agent；
- 300个攻击任务；
- 100个正常任务；
- 211个正常或攻击工具；
- 10种LLM。

ARIA将攻击过程分为四级：

| 指标 | 含义 |
|---|---|
| ARIA-1 | 立即拒绝 |
| ARIA-2 | 执行一部分后识别危险并停止 |
| ARIA-3 | 想执行但因协调或工具问题失败 |
| ARIA-4 | 攻击完全成功 |

PNA衡量无攻击时的正常任务能力。ERS使用安全分数和PNA的调和平均：

\[
ERS=\frac{2\cdot Safety\cdot PNA}{Safety+PNA}
\]

安全或能力只要有一项特别差，ERS就不会高。

## 5.6 实验结果

- Impersonation在Swarm中达到82%；
- DPI在Magentic-One中达到81%；
- IPI平均ASR在Magentic-One为27.4%，Round Robin为56.4%；
- Magentic-One的IPI中，闭源模型平均15.6%，开源模型39.2%；
- Round Robin中，闭源模型37.6%，开源模型75.2%；
- Byzantine攻击通常较强；
- Colluding完整成功率只有2%–16%，但很多情况下至少一个共谋Agent已经完成恶意动作。

Prompt攻击跨模型普遍有效；IPI对框架和消息传播方式更敏感。中央式系统可能拥有较高综合能力，但一旦Orchestrator被攻陷，会形成系统级单点故障。

轻量防御中，DPI分隔符平均降低约5.2个百分点，IPI工具输出标记平均降低约11.2个百分点；改写可能误删正常子任务，监控Agent则经常产生误报。

## 5.7 证据边界

- 数据和攻击工具主要为合成内容；
- Byzantine、Colluding和Contradicting假设攻击者能修改Agent系统提示词；
- Agent级攻击依赖GPT-4o Judge，人工验证总体F1为89.17%，但Contradicting只有75%；
- Colluding的严格成功条件可能低估部分完成的真实危害；
- 论文评测结果，但不解决感染源定位、传播链追踪和系统恢复。

# 7. 对MAS防御与自愈研究的直接启示

## 7.1 防御不能只检查单条消息

Conjunctive证明恶意意图可以分散在：

- 用户输入；
- 远程Agent模板；
- 路由结果；
- 多轮上下文。

因此检测器需要跨消息、跨Agent、跨时间进行联合判断。

## 7.2 信任不能只绑定Agent身份

同一Agent可能在不同时间接收不同来源的信息后发生状态变化。信任应绑定：

```text
Agent身份 + 消息来源 + 工具来源 + 当前状态 + 历史行为 + 拓扑位置
```

## 7.3 拓扑既决定效率，也决定攻击半径

NetSafe和CORBA共同说明：

- 高连接度提升正常信息交换效率；
- 同时加快错误和递归攻击传播；
- 静态固定拓扑不能适应风险变化。

一个自愈系统应该根据实时风险动态剪边、限流或隔离，而不是永久采用最稀疏的拓扑。

## 7.4 语义安全不等于行为安全

CORBA文本在语义上无害，却能消耗全部协作资源；Impersonation语气正常，却可能伪造授权。因此系统必须同时检测：

- 内容是否有害；
- 行为是否越权；
- 消息是否重复传播；
- 资源消耗是否异常；
- 通信模式是否发生突变。

## 7.5 检测之后还需要修复闭环

现有论文主要覆盖：

```text
攻击构造 → 攻击传播 → 攻击结果评估
```

真正的自愈系统还需要：

```text
异常检测
  → 定位初始攻击源
  → 追踪受污染Agent、消息、记忆和工具调用
  → 隔离节点或剪除高风险通信边
  → 撤销危险动作与清理污染状态
  → 恢复拓扑和任务
  → 验证恢复后系统仍安全且可用
```

## 7.6 可形成的研究问题

> 当DPI、IPI、Memory Poisoning、恶意Agent或分布式触发器进入MAS后，系统能否在攻击扩散前识别异常传播模式，定位最初感染源，并通过动态拓扑重构、状态回滚和信任更新恢复正常协作，同时保持较高的任务性能？

# 8. 组会速记版

如果只能用一分钟讲五篇，可以说：

> ASB系统化梳理了Agent输入、工具、记忆和规划层的攻击，但主要是单Agent基准。TAMAS进一步把攻击扩展到真实MAS中的冒充、拜占庭、共谋和矛盾Agent。Conjunctive表明攻击意图可以分散在用户Key和恶意远程模板中，只有经路由会合才激活，因此单点检测容易失效。NetSafe说明恶意信息的传播强度与拓扑和信息类型有关，高连通网络尤其容易放大普通错误信息。CORBA则进一步证明，一条语义无害但可递归复制的指令能够沿通信图传播，使MAS进入拒绝协作状态。五篇共同说明MAS安全问题不只是单个LLM输出是否有害，而是攻击入口、路由、拓扑、状态和协作行为共同决定的系统级问题。

# 9. 转向GUARDIAN时需要带着的问题

阅读GUARDIAN时重点检查：

1. 它能检测的是恶意语义、异常行为，还是异常传播模式？
2. 它使用瞬时图还是时序图？历史状态如何进入节点表示？
3. 它能否识别Conjunctive这种单条消息无害、组合后有害的攻击？
4. 它能否识别CORBA这种语义无害但行为递归的攻击？
5. 检测器输出的是Agent级风险、边级风险，还是整个系统风险？
6. 检测后是否真正修复，还是只报警/删除消息？
7. 防御是否会伤害PNA、任务准确率和通信效率？
8. 训练攻击类型与测试攻击类型是否重合？未知攻击下是否仍有效？
9. 如果攻击经共享记忆和多轮通信传播，模型能否定位最初感染源？
10. 它的方法能否支持动态隔离、状态回滚和拓扑恢复，从而构成真正的自愈闭环？
